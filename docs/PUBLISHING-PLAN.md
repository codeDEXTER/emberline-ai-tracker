## Recommended release model

Publish a curated marketing showcase first; keep implementation and internal
ledgers private until the owner approves reuse terms. Do not make this entire
repository public simply to publish its README. Review screenshot text for private
project names, people, paths and operational details. Rewrite internal guide and

## Licensing decision (not adopted)

- Restrictive source-available/commercial terms best match the stated desire to
  prevent unauthorized redistribution or competing repackaging. Have counsel define
  permitted evaluation/internal use, modification, distribution, commercial use,
  attribution, termination and warranty/liability terms. This is not open source.
- AGPL-style copyleft permits copying and commercial use but imposes source-sharing
  obligations in covered circumstances. It is an alternative if reciprocal openness,
  rather than preventing copying, is the objective.
- MIT/Apache-style permissive licensing is not aligned with preventing reuse.
- No license grants no general reuse permission, but public GitHub repositories
  still permit viewing/forking under GitHub's terms. It is not copy prevention.

Licenses provide legal conditions, not technical prevention. Ideas/workflow concepts
are not protected in the same way as original code and prose. Confirm ownership and
third-party obligations, especially for dependencies, contributions and generated
assets, before offering rights. No LICENSE has been added and no rights are granted
by this planning document. Obtain qualified legal advice for the final terms.

Sources: [GitHub's licensing guidance](https://choosealicense.com/no-permission/),
[Open Source Definition](https://opensource.org/osd),
[GNU license guidance](https://www.gnu.org/licenses/license-recommendations.en.html).
