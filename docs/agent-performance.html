How the agents are performing

Measured from 12 days of session transcripts, 464 agent dispatches and three repositories. Role adoption went from nothing to near-total, the decision load on the sponsor collapsed from 62 prompts a day to 2, and the agents are finding defects the person writing the rules did not. Dispatches have doubled since the 7 August edition and the trend has held.

Supporting the performancewhat is actually costing them

Four things measurably limit the agents right now. All four are counted from the same transcripts as everything else above.

LimitOccurrencesWhat it costs, and the fix
GitHub API rate-limiting156 Queries fail outright — one for this report did, and had to fall back to local git. If issues become the single backlog, this ceiling is load-bearing. Fix: cache issue reads, and pass --limit explicitly (gh silently caps at 30, which under-reported the backlog by a third in the 7 Aug edition).
600-second watchdog stalls35 The most expensive item here. An agent does the work, then dies mid-report — so the work exists but its findings and token counts never arrive. Already seen once in AGENT-LOG: an agent finished, stalled closing out, and its numbers were lost. Fix: have long roles checkpoint findings to a file as they go, not only in a closing message.
Dispatch failed — agent type not found6 A definition exists on disk but the session's searched directories were fixed at start, so a project-scoped agent is invisible to a session rooted elsewhere. Cost two arms of the workflow bake-off. Fix: keep shared roles in common-rules/agents/, which every session resolves.
Context exhaustion1 Rare. Not currently worth engineering against.

The biggest gap is not in the table, because nothing measures it. spend report --by-agent counts dispatches, not tokens. So we can say code-engineer ran 176 times and quality-manager 85, but not what either cost. Every efficiency question — is the gate worth its price, is research-agent expensive — is currently unanswerable.

Sub-agent transcripts do carry usage; they simply are not joined back to the dispatching role. That join is the single highest-value addition to this report.

What this does not showstated up front

High adoption is not proven value. The workflow bake-off ran five process architectures over one frozen specification, judged by a sealed suite. All five scored 22/22; cost ranged 66,816 to 1,160,499 output tokens. On the one task where quality could be measured objectively, more agent process bought nothing measurable. What has improved is compliance with the design — not a demonstrated quality gain on ordinary work.

  • Sponsor messages have not fallen. 350 on 7 Aug, 379 the same day on the corrected count, 277 on 9 Aug. Formal prompts collapsed; total engagement did not. The AI stopped putting buttons on screen; it did not stop needing the sponsor.
  • Dispatch counts measure activity, not outcome. Nothing here shows a task done better because a role ran — only that roles ran.
  • Test counts are a proxy. 1,737 passing tests says the suite is large and green, not that it is well-aimed. Two criteria in the bake-off's own sealed suite turned out to pass against a do-nothing stub.
  • Twelve days, one operator, three projects. Direction, not a multiple.
Method

Every figure is parsed from ~/.agent-data/projects/*/*.jsonl session transcripts and local git log, not from any agent's self-report — during this period every workflow-experiment arm mis-stated its own wall-clock, and one arm's headline bug finding was overturned by direct probe. Token and dispatch counts use the corrected attribution that landed 7 August; figures published before it understated spend concentration. Colours are the reference categorical palette's slots 1 and 2, unmodified; the validator could not be executed here (node is not installed on this machine), so this relies on that palette's documented validation rather than a fresh run.

Why this file is committed. The 7 August edition was left untracked in docs/ and was deleted — along with two other untracked reports — before it could be updated. Untracked files in this repo do not survive.
