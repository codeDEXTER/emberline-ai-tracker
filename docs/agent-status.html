This is probably a success, not a failure — but it should be a decision, not a drift. Tests exploded over the same period: finance-tracker 666 → 4,428, pockets 0 → 77 test files. Verification is happening; it stopped going through the roles.

The land guard ("changes code but no test") and the "probe you ran is the test" rule do structurally, for free, what test-engineer was dispatched to do. The mechanism displaced the ceremony — which is what the workflow bake-off predicted when five process architectures scored identically and cost varied 17×.

Where it is failingthree things

1 · Two of three trunks are red.

common-rules: 4 failures of 249. Commit f9ed133 on 30 August changed closes_trailer to stop treating "issue" as a closing keyword, did not update tests/test_land.py, and landed anyway — leaving 3 tests red. finance-tracker: 2 failures of 4,428.

2 · common-rules is the one repo its own guards do not protect.

bin/land exits 3 for common-rules by design — the reserved-path rule that stops the AI merging its own rules. The consequence is that the repository hosting every gate is the only one where no gate applies at merge time. That is exactly how f9ed133 landed red.

3 · pockets has 77 test files and no CI.

The identical gap common-rules had before 10 August — and precisely how its trunk sat red for two days with nobody noticing.

Also drifting: docs/workflow.html stamps rules version 166 while the rules are at 178. Twelve versions behind, on the page whose own rule says a drifted bird's-eye view is worse than none.

Verdict

Useful — but not for the reason it was designed. What is paying off is the executable layer: bin/land (601 uses), the test-requirement guard, CI, and the new milestones (92) and proposalcheck (76). What is not paying off is the eight-role org chart: two thirds of dispatches go to one role and the two verification roles are shrinking.

Same conclusion the bake-off reached in August and the same one this period re-proves: things that run get used; things that instruct get ignored.

One thing is measurably dead. spend agentlog — the generated cost log — has been run once in three weeks. It works, it is tested, and nobody wants it. It should be removed or wired into something that runs on its own.

Two fixes worth making, both small: give pockets a CI workflow, and decide whether common-rules should stay exempt from its own gate. That exemption is currently costing a red trunk, and a narrower rule — reserved for merging, but tests still enforced — would keep the protection without the cost.
