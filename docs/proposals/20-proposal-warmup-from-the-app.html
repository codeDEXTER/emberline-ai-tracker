Decisions

D1The tracker publishes itself where you read it?
Accept. tracker render writes a file; you read an artifact. When the digest changes, the page is republished to the same URL — so "publish the tracker" is never typed again.
evidence

App session c45825a1, 13 Sep: 22 unique sponsor turns after removing the compaction replay; five asked for the plan updated or the tracker published — the most repeated thing typed, in a project that already had a tracker. The engine session asked for status eleven times across 6–13 Sep.

D2One model-routing table, per project, measured?
Accept. The ledger's routing table is the only one; prompts, pages and checkers read it, never restate it. A project records what it found usable — the app routes Trivial to Haiku only for bookkeeping, never UI code — and the checker refuses a mismatch without a reason.
evidence

Routing in the app: 70-r9-delivery-plan.json model_routing (with the note "Trivial = bookkeeping only … Never UI code"), tools/build_plan.py MODEL_FOR and its refusal "model … disagrees with complexity … and has no model_override_reason", plus the plan .md, CLAUDE.md and 70-lead-prompt.md. Session: 83 Agent calls, sonnet 54, opus 27, haiku 0.

D3The agent tag is checked when the agent is spawned?
Accept. A PreToolUse hook on the Agent tool reads the prompt's first line and warns, with the item's tag from the ledger, when [ruflo · tier · model] ID title is missing. Warn first; a week's measurement decides whether it refuses.
D4Every blocked item and decision names whose call it is?
Accept. An owner on blocked rows and decision asks: sponsor, lead, or a session by name. The card's "yours" line lists only yours; the rest becomes a message to its owner.
D5A project can switch parts of the standard off, on the record?
Accept. A switches block — issues, publish, ruflo — each with who, when and the quote. Tools honour it; the card prints what is off.
D6Done needs evidence, and each row declares its verification level?
Accept. The app's rule, generalised: a row is done only when its evidence flags are true, and every row names the level it must reach from the project's ladder. tracker validate refuses done without it — today it only asks that the log be non-empty.
evidence

tools/build_plan.py refuses "is done but evidence incomplete" and a verify level outside VL1–VL6, and requires native evidence for VL5/VL6. 70-r9-delivery-plan.json carries verification_ladder (6 levels, each with what, proves and tool — VL1 "static and unit", tool flutter test), verification_rules (9, e.g. "A browser is never a verification surface for this product") and receipts (commit, build, method, captured_by). common-rules' ledger.validate only checks that a done row's log is non-empty.

D7Requests between sessions get their own lane?
Accept. A requests lane — from, to, what it unblocks, state, answered-by — replacing ad-hoc notes. The app already keeps ten external_dependencies and a requests document; the standard's depends can only name an item in the same ledger.
D8Readiness is computed, and "merged, awaiting evidence" is visible?
Accept, keeping four statuses. Gates, quality floors and receipts become ledger data, and the card prints a computed readiness beside the counts. "Merged, awaiting evidence" is a merged flag on an in-progress row, not a fifth status — the vocabulary stays one.
evidence

tools/build_plan.py score(): readiness = 70 × weighted work (done full, active-with-tests half) + 15 × gates passed + 10 × floors met + native receipts on primary surfaces; merged_waiting lists rows merged but not done. The plan JSON holds gates (7, each passed/evidence), quality_floors (6, each command/met) and native_receipts. Adding a fifth status would break every tool built on the four (render, check, sync, checkpoint, warmup).

D9A project declares its own entry points, and the standard reads them?
Accept. One file, .common-rules.json, growing from today's .common-rules-test: read order, where the safety rules live, the quick and merge gates, the plan checker and page generator. The card and tools use the project's own instead of assuming HANDOFF.md, one gate and the standard's renderer. .common-rules-test keeps working.
evidence — now live in the app

After the app migrated (36aa2dd), the pointer block migrate appended to its CLAUDE.md reads "Read, in order: HANDOFF.md → docs/OPERATING-RULES.md → the ledger(s)…" — three lines below the app's own "Read this first, then SPONSOR-CONSTRAINTS.md", with HANDOFF.md marked Historical. The contradiction sits uncommitted, waiting for the sponsor. App CLAUDE.md: "Read this first, then SPONSOR-CONSTRAINTS.md"; HANDOFF.md is marked Historical. Safety rules are under "Hard safety rules" in CLAUDE.md (and HANDOFF line 123). Two gates: agents run gate.sh --quick (also the tracked Stop hook), the lead runs gate.sh before merging. build_plan.py already validates more strictly than ledger.py and generates the page. The engine, too, keeps a commit gate and a merge gate — .common-rules-test holds only one.

D10The lead prompt allows parallel high-tier agents?
Recommend accept. The template says one C3 at a time, run by the lead, and never a subagent on the lead's model. The app runs up to six agents with Opus phases in parallel, each reviewed by a report-only agent. Replace both lines with the app's: parallel C3 when file ownership is disjoint; the lead merges, reconciles and decides.
evidence

common-rules templates/lead-prompt.md §2 and §3 (the two quoted lines). App 70-lead-prompt.md: up to six agents, Opus-level phases in parallel, independent review by a report-only agent of at most the same tier with at most two rounds. It also matches the standing split "Sonnet codes, Opus decides".

D11The mandatory Ruflo loop is a command, not a paragraph?
Accept. Ship the app's wrapper as bin/ruflo-item start | done | note | recall: it stops the daemon on every exit, done runs the declared merge gate first, and recall lists keys before semantic search — which misses exact keys like item:Q1:done.
evidence

App tools/ruflo_task.sh: trap on EXIT runs daemon stop; done runs tools/gate.sh before post-task and memory store; recall runs memory list before memory search, with the comment that semantic search misses exact keys. App CLAUDE.md makes an item without both entries not done. Common-rules today: the loop is prose in templates/lead-prompt.md; in proposal 19's build one agent's loop errored with nothing noticing, and the engine's Ruflo ledger recorded 0 usable memory hits across 43 agents.

D12Generated files ride the ledger's own commit?
Accept. A pre-commit step: when a ledger is staged, regenerate its tracker page and the checkpoint and stage them with it. One commit per ledger change, never a separate "refresh checkpoint" commit — and the card never shows them stale between the two.
D13derecord keeps Ruflo's runtime state out of git?
Accept. Ruflo is mandatory, so every project that runs it writes daemon state, metrics and memory databases. derecord adds the ignore lines common-rules adopted in PR #149 — runtime state only; a project's shared Ruflo config stays committable.

The decisions, as asked

  1. D1. The tracker republishes where the sponsor reads it whenever its digest changes.
  2. D2. One model-routing table per project, in the ledger, recording what the project found usable; checkers compare model with class.
  3. D3. A PreToolUse hook on the Agent tool warns when a prompt's first line lacks the [ruflo · tier · model] ID tag.
  4. D4. Blocked rows and decision asks name their owner: sponsor, lead, or a session by name.
  5. D5. A ledger switches block lets a project turn parts of the standard off, with who, when and the quote; tools honour it.
  6. D6. Done needs evidence, and each row declares its verification level from the project's ladder.
  7. D7. Requests between sessions get their own lane in the ledger.
  8. D8. Gates, quality floors and receipts are ledger data; readiness is computed; merged-awaiting-evidence is a flag, keeping four statuses.
  9. D9. A project declares its read order, safety rules, quick and merge gates, plan checker and page generator in .common-rules.json.
  10. D10. The lead-prompt template allows parallel high-tier agents on disjoint files, each with a report-only reviewer.
  11. D11. The mandatory Ruflo loop is a command: bin/ruflo-item start | done | note | recall.
  12. D12. Generated files ride the ledger's own commit: a staged ledger regenerates and stages its page and checkpoint.
  13. D13. derecord keeps Ruflo's runtime state out of git; shared Ruflo config stays committable.
