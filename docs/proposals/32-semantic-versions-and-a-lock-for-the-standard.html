What was found

  • Another finding. Say what was not verified, too.

Recommended: the option, and the one reason that decides it.

Decisions

Each numbered line is one thing the sponsor answers. Keep the numbers stable once shown: answers and ledger items cite them.

  1. D1. The first decision, as a question with one answer.
  2. D2. The second decision. Add or remove lines; never leave the list empty.

Decided

Not decided yet. When the sponsor answers, change this page in this order.

  1. The date, first. Copy this line into the head, directly under the status meta, and put the real date in place of YYYY-MM-DD: 
    <meta name="proposal-decided" content="YYYY-MM-DD">
    Without it, bin/proposalcheck treats the page as decided before its rules existed and checks nothing.
  2. Then the status. Replace the proposed status meta with this line: 
    <meta name="proposal-status" content="accepted">
    and change "proposed" to "accepted" in the title, the heading, and the "Proposal NN · proposed DATE" line under it.
  3. Write both lines exactly as shown. Do not self-close them with />: bin/proposalcheck does not read that form, and the page would read as undecided.
  4. Give this section the id decided, and replace this text with the sponsor's answer quoted from disk, the date, and what each of D1, D2 ... was decided as.
  5. Add the items to the ledger beside this page (same number, .json).

The id is added by hand, on purpose. A page that shipped with an empty answers block would pass bin/proposalcheck while recording nothing.

Completed in part. A proposal closed as completed in part also needs a block with the id exceptions beside the <ol class="decisions"> list, naming what was not built and why. The same rule applies: add it when it is true, never in advance.
