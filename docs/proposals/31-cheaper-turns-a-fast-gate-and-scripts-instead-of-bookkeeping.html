What was found

  • The tests already run locally and cost nothing. The suite is plain unittest: no network, no model calls, no tokens. The premise of the question is answered by measurement, not by change.
  • One agent turn costs about 134,000 cache-read context tokens to produce a few hundred written ones — read off a single builder record in this session's transcript. Cost therefore scales with the number of turns, not with the work inside them. It is why 72% of this project's spend went to lead orchestration and 25% to implementing.
  • The suite is ~16 minutes, and one file is a third of it. tests/test_warmup.py: 574.9s for 122 tests, 4.7s each, against test_tracker_render's 0.36s. Every test rebuilds a git repo and shells out to three bin/tracker subprocesses in its setUp. Recorded as finding 23/F-06.
  • Sharding does not help yet. bin/quiet --jobs 8 measured 610s wall — no better than serial — because one shard holds that one file, while the other six finished in 15, 27, 66, 129, 164 and 222s.
  • The parallel runner was built and never switched on. bin/quiet --jobs exists from proposal 23's M-01, whose own done criterion was "Suite wall-clock measured before and after on the same commit; merge gate and land use it". Neither happened: its evidence quotes one sequential 1210.2s run, and gates.merge still runs the plain serial discover. Recorded as finding 23/F-07.
  • Two builders spent turns polling a backgrounded suite in this very session, each check re-sending a full context to learn nothing. That is the habit, not an accident.
  • Not verified: what the suite costs after the fixture fix and with balanced shards. O-01 and O-02 must measure it before and after on the same commit — the mistake M-01 made is exactly the one not to repeat.

Options

A · Make the tests cheaper

Fix the slow fixture, balance the shards, wire the parallel runner into the merge gate. Cuts the wait from ~16 minutes towards ~2. Costs nothing in judgment and nothing in tokens directly — it removes the reason a session waits.

B · Make the turns fewer

Forbid waiting on a gate, batch dispatch into one message, and move mechanical bookkeeping — commit-on-green, PR bodies, ledger event text — from model prose into scripts. Attacks the 134k-per-turn cost directly. Rules out nothing; judgment stays with the model in every case.

Recommended: both, in that order. A alone leaves the polling habit in place; B alone leaves sessions with a 16-minute reason to poll. The one reason to do A first: until the gate is fast, "never background a gate" is a rule nobody can follow.

Decisions

Each numbered line is one thing the sponsor answers. Keep the numbers stable once shown: answers and ledger items cite them.

  1. D1. Fix the slowest test file by building its seeded project once and copying it per test, changing no assertion. → O-01
  2. D2. Balance the shards by measured duration, give --jobs an auto default, and point gates.merge and bin/land at the parallel runner — measuring before and after on the same commit. → O-02
  3. D3. Make it a mandatory Standard change that a session runs its gate in the foreground and reads the verdict in the same turn, never backgrounding it to poll. → O-03
  4. D4. Move three mechanical sequences into scripts: commit-and-push only on a green verdict, the PR body drafted from the ledger item and the diff, and the ruflo-item done and ledger event text drafted from the same facts. Each script assembles facts; none decides anything. → O-04, O-05, O-06
  5. D5. Make batching a stated cost rule: every unblocked brief goes out in one message, and branches are reviewed in one pass. → O-07

Decided

Accepted in full on 17 Sep 2026, in the sponsor's words: "Implement all the five recommendations with the recommended decisions." D1 through D5 are adopted as recommended, and option A and option B are both taken, A first for the reason given above.

The seven items are in the ledger beside this page: O-01 and O-02 for the gate, O-03 and O-07 as mandatory Standard changes, O-04, O-05 and O-06 as the three drafting scripts. O-02 depends on O-01, because the sharding measurement is meaningless before the fixture fix.

One boundary, recorded because it constrains every item here: these scripts draft bookkeeping prose from recorded facts. None of them decides whether work is done, whether to merge, or what tier something is. That judgment stays with the model, as it does today.
