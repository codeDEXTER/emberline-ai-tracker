34 · proposed · Testing the agents: does each role do its job, and refuse the work that is not its own

Proposal 34 · proposed 2026-09-19. Eight role agents have been dispatched 2,756 times across three projects and not one line of test covers any of them. This asks the sponsor to decide whether to build an agent test harness, how far it goes — from a free static check to real runs against a seeded fixture — and what may block a merge.

The ask

I want you to look into this folder structure and update the context and also create a tracker and everything for testing all the different AI agents. There is a create a visual proposal for me to visualize what kind of tests you would be running for all the agents and everything and what you would need. So let's start this activity. The sponsor, 2026-09-19, as the argument to /warmup in this session. Recorded verbatim as A-01 in the ledger beside this page.

What was found

  • Eight role agents, one copy. common-rules/agents/*.md holds code-engineer, design-engineer, design-explorer, proposal-auditor, quality-manager, requirements-engineer, research-agent, test-engineer. All eight are byte-identical to the ~/.agent-data/agents/ mirror every session actually loads (diff, 8 of 8 same, 2026-09-19). No project keeps its own copy — so drift is possible and today is zero.
  • 2,756 dispatches, zero tests. bin/spend report --by-agent: common-rules 1,566, PhotoVault app 455, PhotoVault engine 735. code-engineer alone accounts for 1,162 of them; quality-manager 417; proposal-auditor 7.
  • Nothing loads an agent file. 87 test files under tests/; grep -rn "agents/[a-z-]*\.md" tests/ returns nothing. The 12 items of bin/conformance do not mention agents at all.
  • One of eight pins a model. Only code-engineer carries model: sonnet. The other seven inherit whatever the dispatcher passes, so the C1–C4 tier table in every ledger is honoured by convention, not by the file.
  • The agents carry contracts nothing checks. quality-manager must close every report with a verbatim line — "This is a recommendation — merge approval is the sponsor's decision." — and must never edit a file. Both are assertable. Neither has ever been asserted.
  • A second, unowned population. 17 further agent files sit under PhotoVault app .claude/agents/ (consensus 7, sparc 4, swarm 3, testing 2, core 1), shipped by claude-flow, outside the standard. The spend log shows them being picked anyway: code-analyzer 15, sparc-coder 8, coder 7, system-architect 6, researcher 4, tester 3, hierarchical-coordinator 1, planner 1.
  • Not verified. Whether any of the 2,756 calls ever broke a role boundary — a test-engineer patching code, a read-only agent writing — is unknown. No transcript has been asserted against. The failure rate today is unmeasured, not zero.

What the tests would be

Six layers. The cheap ones run on every commit and cost no model calls; only the bottom two dispatch a real agent, and only when an agent file changes.

What each agent must prove

One thing it must do, and one thing it must refuse. The refusal half is the point: every role in this standard exists because some other role must not do that work.

research-agentthree structurally different approaches, each with its cost, plus the open questionswriting REQUIREMENTS.md; picking the direction
requirements-engineernumbered requirements, each with a criterion someone else could later provedesigning the solution; choosing between directions
design-explorerthree concepts that differ in structure, not in colourproducing a buildable spec

proposal-auditorevery divergence found and classifiedfixing requirements; approving anything

test-engineera structured bug report with file and linepatching the code it just found broken
quality-managerverdict, evidence per criterion, and the verbatim closing lineediting any file; approving the merge

What would be needed

  • A fixture — the gym. tests/fixtures/agent-gym/: a small repository with a REQUIREMENTS.md of six numbered criteria, an implementation that meets four and breaks two in known ways, a locked design artifact, and a LESSONS.md. Every planted defect is recorded with the layer and agent it is there to catch.
  • A runner. bin/agentcheck: copies the fixture to a throwaway directory, dispatches one agent against it at a real model, and captures three things — the transcript, the tool calls, and git status before and after.
  • A scorer that asserts first. Deterministic wherever it can be: a diff, a tool name, a verbatim string. An LLM judge only for the rubric lines that cannot be asserted — "are these three concepts structurally different?" — with the judging model and date recorded beside the verdict.
  • A results file the tracker renders. One row per agent per layer: pass, fail, or not run, with the date, the model and the cost. The tracker page already renders findings; this is the same shape.
  • A budget. L0, L1 and L5 are free. L2 is one cheap call. L3 and L4 are eight real runs, one per agent, and run only when agents/*.md changes — not on every commit.
  • A decision on the 17 unowned files. The claude-flow agents under PhotoVault app are being picked by dispatchers today and are covered by nothing. They are adopted, deleted, or explicitly excluded — leaving them unowned is the one option that keeps the gap.

Options

A · Static only

L0, L1 and L5 as a 13th conformance item every project inherits. No model calls, no fixture, runs on every commit. Catches drift, a missing model pin, a tool that no longer exists. Proves nothing about behaviour — the 2,756 dispatches stay unmeasured.

B · Static plus routing

A, plus a labelled corpus of task sentences scored against the descriptions, with negative cases. Catches the most common real failure — the wrong role picked — for about one cheap call a night. Still says nothing about what an agent does once it is running.

C · The gym

A and B, plus real runs against the seeded fixture scored on both halves: does the job, refuses what is not its own. The only option that can catch a test-engineer that patches code. Costs a fixture, a runner, a scorer, and eight runs per agent change.

Recommended: C, built in that order — A first because it is free and is the only layer that can gate every commit, then B, then the gym behind them. Building the gym first would mean the expensive layer is the only one running.

Decisions

Each numbered line is one thing the sponsor answers. Keep the numbers stable once shown: answers and ledger items cite them.

  1. D1. How far: A, B, or C? (Recommended: C, phased A → B → C.)
  2. D2. Scope: the eight role agents only, or the 17 claude-flow files under PhotoVault app as well — and if the latter, adopted or deleted?
  3. D3. Is an LLM judge allowed for the rubric lines that cannot be asserted, and at which model? (Sonnet, per the no-Opus-for-subagents ruling.)
  4. D4. Does a failing agent test block a merge, or report only? Per layer, if the answer differs — L0 and L1 are safe to block; L3 and L4 are not, until their false-positive rate is known.
  5. D5. Does this live in common-rules as a 13th conformance item every project inherits, or as a common-rules-only test suite?
  6. D6. What is the ceiling on a full gym run, and how often may the behavioural layers run — on every agent-file change, or weekly?
