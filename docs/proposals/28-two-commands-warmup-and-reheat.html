28 · accepted · Two commands: warmup and reheat

Proposal 28 · accepted 2026-09-15. Two commands replace three names: /warmup for a fresh lead, /reheat for a running one. The standard's checks run inside both. Hooks run the right one when a lead starts, resumes or compacts, and the dispatcher starts a new lead with /warmup <item>, so nobody has to type. Both accept free-text context.

The ask

So currently there are standard, warmup and reheat… I want to keep just two warmup and reheat. Standard should always be included. Also if the lead needs to be created again then how will it work with these two or it happens automatically. Show me a visual proposal The sponsor, 15 September 2026, in the Common Rules rework session; proposal 28 ask A-01.

What was found

  • Two commands exist today, /warmup and /standard (skills/warmup, skills/standard). "Reheat" is not a command: it is the sponsor's word for re-warming a running session (proposal 20, ask A-02, "reheat the photovault app and engine"). /warmup already has a mid-session mode (bin/warmup --since).
  • /standard is typed once per project by the sponsor: conformance, a 12-item refactor, and every later Standard change queued first.
  • Nothing runs by itself. hooks/sessionstart only nudges toward /warmup; hooks/precompact writes the checkpoint before a compaction.
  • The shared checkout projects read rules from, common-rules, sat 14 commits behind origin/main on 15 September, so no project saw proposal 23's Standard change until it was pulled by hand.
  • Proposal 24 (accepted) already decided a thin dispatcher, short item leads, a closing check before a lead ends, and that the dispatcher starts the next lead without asking.
  • Not verified: that a SessionStart hook can run a full warm-up within Claude Code's hook time limit. R-03 measures it first.

Options

A · Two commands, standard inside, hooks run them

/warmup for a fresh lead (full read and card), /reheat for a running one (what changed). Conformance and new Standard changes are checked and queued in both. SessionStart runs warmup on startup and reheat on compact or resume; a rules change mid-session triggers reheat at the next stop.

B · Keep three commands

/warmup, /reheat and /standard side by side. Rules out: the one-name habit the sponsor asked for.

C · One command that decides

/warmup detects a fresh or running session and does the right amount. Rules out: asking for a short refresh on purpose.

Recommended: A. It keeps the two names the sponsor asked for, folds the standard in, and removes typing from a lead's whole life.
