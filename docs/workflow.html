code sessionworktree

Its own folder and its own branch

EnterWorktree is the first action on any project repo — no direct-to-main work, no two chats sharing a checkout. Copy in the gitignored files the run needs (.env, data dirs) immediately, or a fresh worktree fails in ways that look exactly like real bugs.

How far has this moved from what you accepted?

Read-only, decides nothing. Classifies every divergence — faithful, elaboration, drift, silent decision, gap — so the next decision runs on evidence rather than on the project manager's own opinion of its own pipeline.

Requirements and design accepted, together

quality-managerthe gate

Pre-merge, report-only

Cheap preconditions first (commit state, merge-base), then outcome-not-surface verification. Fixes nothing, approves nothing — its verdict is a recommendation. Behaviour changed means re-gate; a docstring or changelog line does not.

youmerge

Merge, then the clean copy is refreshed

Approving the merge is yours. The task is not finished at the merge: rebuild from main, replace the installed copy, restart it, register it as stable. A merge that leaves the installed app on last week's build has finished the git work only.

The project manager is deliberately not on this list. There is no project-manager.md — a subagent cannot talk to you, and deciding what reaches you is the role's central job, so it sits in the conversation. Invoked with the Agent tool and subagent_type; the behavioural test is blunt — if the session itself is calling Edit, it is no longer the project manager.

How much ceremonylight is the default
FeatureFull pipeline, every role the task calls for.
Small fixCode engineer + quality manager only.
Research / proposalResearch and/or requirements. Nothing merges, so nothing to gate.

Phase sets the default tier — prototype defaults to light, production to full — and phase is a property of the surface being changed, not the whole project. Published research found full-ceremony role pipelines reduced correctness for most models, which is why the tiers exist at all. code-engineer is pinned to sonnet; a separate reviewer catches more of a weaker writer's mistakes than a stronger one's, and that is what makes the pin safe. Never downgrade test-engineer or quality-manager — they are the mechanism the whole trade-off depends on.

The two toolsrules nobody has to remember
rulecheck                    # am I on the current rules? prints what changed
rulecheck --align            # record this version — only after actually reading

apprun start --project P --phase stable|test|proto --port N --pid N [--demo]
apprun list                  # what you still owe
apprun stop --all            # process + window, before you report
apprun sweep [--clear]       # orphans from dead sessions; --clear needs your yes

Both exist for the same reason: a rule that depends on a session remembering is a rule that decays. Neither is complete — nothing forces a session to call apprun start in the first place, and an unregistered instance is invisible to every later cleanup. That is the honest remaining gap in both.

The short listif you remember nothing else
  • No direct-to-main, ever, and no two chats sharing a checkout.
  • An accepted proposal is not settled requirements. Requirements, then design, then L2 — never straight to code.
  • One proposal per topic, however many agents ran, and it survives across sessions until decided.
  • Show, don't summarise. Artifact over prose; demo before approval; the render, not a description of it.
  • Stop only what you started — and stop the window too.
  • Nothing about issues, merges, promotions or these rules happens without you.
How this page stays true
