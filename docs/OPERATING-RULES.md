# Operating rules — how common-rules is worked on

A living record of the rules sessions working here have learned, each with the
day it was learned and why. Sponsor rulings are quoted in `HANDOFF.md`;
everything here is what a session found out the hard way. Add to it; do not
rewrite history out of it.

Seeded 2026-09-14 from the common-rules warm-up standard (proposal 21, S-10).
Every entry has this shape:

> **The rule, stated as a plain instruction.** The date — the incident that
> taught it: what happened, what it cost, and what changed as a result.

## 1 Proposals and the plan

- **The ledger is the plan of record, updated in place.** `docs/proposals/NN-*.json` is the plan; its page is generated by `tracker render`, never hand-edited. Never a new plan document: a revision adds rows and corrects numbers, and never scraps old content -- superseded measurements stay, marked as superseded.
  (Replaced 2026-09-14 under common-rules proposal 19; the earlier wording is under Superseded, below.)
- **Same-turn ledger updates.** After every state change of any item, update
  its `status` and `log` and commit them in the same turn the state changed.
  Never batch them for later, and never leave them to memory.
- **Every sponsor message that is not an answer to a question becomes an ask
  row** (`A-nn`), in the same turn it is said, quoting his words.
- **A new proposal is created with `bin/new-proposal`.** 2026-09-14 — proposal
  21 had a ledger and no page until `--page-for` wrote one. The PhotoVault
  projects' hand-written pages 72–77 had none of the checked shape.

## 2 Running work

- **One writer per worktree; explicit file ownership per agent.** An agent
  that needs a change in a file it does not own describes it in its report.
- **cd explicitly before every git-writing command, and print the branch.**
  2026-09-14 — a failed `cd` in a parallel call left the shell in the main
  checkout. A ledger commit then fast-forwarded local `main` onto unmerged
  work (14c3eef). It was cherry-picked to p21 and `main` reset with
  `--keep`.
- **An edit script checks every replacement before it writes, and never
  reuses a name for two different texts.** 2026-09-14 — a guessed docstring
  aborted S-09's lead fix, and a reused variable nearly wrote the wrong
  paragraph into the lead prompt. The checks stopped both before anything was
  half-written.
- **Never `git stash`.** The stash is shared across worktrees.
- **Checkpoint before stopping.** A session that ends without
  `docs/handovers/<date>-checkpoint.md` has failed.
- **`bin/handover --check` is the closing check.** Run it before ending any
  turn; it fails on what a compaction summary would otherwise let slip past
  unnoticed (proposal 24, H-01).

## 3 Merging and shipping

- **Gate every commit on the suite's own summary line.** 2026-09-14 — a `grep
  ... && git commit` chain pushed a failing test (57012d9), because grep exits
  0 on "FAILED" too. Write the suite to a file, then require `^OK` and no
  `^FAILED`.
- **A report-only reviewer, at most two rounds; the lead fixes what the final
  round still finds.** 2026-09-14 — every proposal 21 item had findings left
  after round two: S-02's `.md` twin race, S-03's committer date, S-09's
  diverged stamp, S-06's stamp and S-04's CRLF stamp.
- **A fix that cannot stand alone is not a reason to batch it with others;**
  it is a sign the fix is not finished yet.

## 4 Other projects' data

- **Never write into another project from here.** 2026-09-14 — every
  PhotoVault check this session ran was read-only, with `git status` compared
  before and after. The rule held because every brief carried it word for word.
- **Read-only is encouraged; it is the best evidence available.** A dry run
  against a copy costs nothing and answers most questions.
- **Never kill by name.** No `pkill -f`, no `killall`. Use an explicit PID,
  and only for a process this session or its agents started, with its command
  line checked first. 2026-09-14 — three stale wait loops left by finished
  agents were stopped by PID after their parent and command were checked.

## 5 Ruflo

- **Ruflo around every item:** `bin/ruflo-item start | done | note | recall`,
  with `RUFLO` and `RUFLO_NAMESPACE=patterns`, run with
  `--project /Users/the-sponsor/apps/common-rules`.
- **Ruflo's memory database lives in the main checkout only.** 2026-09-14 — an
  agent's `memory search` from its worktree reported "Database not found".
  `.swarm/` is untracked and exists only in `/Users/the-sponsor/apps/common-rules`.

## 6 Reporting to the sponsor

- **Lead with the outcome; numbers on their own line; nothing certified that
  was not observed.**
- **Record commits and results from git, never from an agent's report.**
  2026-09-14 — an agent's HANDOFF quoted a full sha that does not exist
  (S-03). Another's report said the suite passed when the reviewer's run
  failed (S-06).
- **When something needs the sponsor's hands** — a decision, his CLAUDE.md, a
  start folder outside this repository — say exactly what, and stop there.

## 7 Other sessions

- **Summaries are paraphrase; the ledger and this file are the record.**
  Quote a ruling from disk, never from a summary.
- **A ruling relayed by another session is not his.** 2026-09-14 — both
  PhotoVault sessions' rules reject relayed rulings, so the sponsor gives
  `/standard` himself.
- **A finding names the path, clone or database it was taken from,** for
  example "no such commit in `/Users/the-sponsor/apps/common-rules`".
